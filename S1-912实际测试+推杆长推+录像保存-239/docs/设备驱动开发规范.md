# Snappy v1 设备驱动开发规范

> 文档版本：1.0
>
> 更新日期：2026-08-17
>
> 适用范围：`rk3588/drivers`、`rk3588/control` 中的设备接入代码，以及对应的 fake、协议测试和硬件在环测试

## 1. 目的与规范用语

本文把本地 `exa/` 目录中已经提供的设备资料转换为 Snappy v1 可执行的驱动开发约束。`exa/` 是不纳入 Git 的厂商资料区；本文确认的是设备型号、线协议、编码、量纲、安全边界和验证门禁，CAN 接口分配、RS485 物理端口、现场站号、继电器通道、超时阈值等部署参数仍必须通过配置和实机验收确定。

本文不表示真实驱动已经完成。当前仓库仍以 fake 和 `Unconfigured...` 后端为基线；只有满足本文的“真实后端启用门禁”后，某一设备才可以从 `UNCONFIGURED` 变为可用。

通用命名、文件结构、错误、日志和合并门禁同时受 [设备编码规范](设备编码规范.md) 约束；若两份规范出现冲突，必须先修正文档，禁止由实现者自行择一。

- **必须（MUST）**：违反即属于实现错误或安全缺陷。
- **应（SHOULD）**：原则上必须遵守；偏离时必须在代码评审或变更说明中记录原因与证据。
- **可以（MAY）**：可选实现，不得削弱必须项。

系统边界仍以 [`docs/snappy v1 精简架构设计.md`](snappy%20v1%20精简架构设计.md) 为准：硬件只允许 `snappy-control` 写入；G20 UDP 是主力操控链路，MQTT/TLS 是辅助/人工备份链路；视频只走“RK USB 摄像头 → G20 SDK → Android”。WebSocket、云端视频和远程绕过安全状态机均不属于设备驱动范围。

## 2. 资料权威顺序与事实分级

### 2.1 权威顺序

发生冲突时，必须按以下顺序处理：

1. Snappy 已确认的系统安全边界和接口契约。
2. 与实物型号、版本完全匹配的厂商正式资料。
3. 同厂商的通用协议资料。
4. 厂商或项目示例代码。
5. 单次现场日志、经验值或推测。

低优先级资料不得静默覆盖高优先级资料。无法消除的冲突必须进入配置门禁或禁用相关功能。

### 2.2 四类事实

驱动代码、配置 Schema 和评审记录必须区分以下四类值：

| 类别 | 含义 | 实现要求 |
|---|---|---|
| 厂商确认 | 正式资料明确规定的帧、寄存器、缩放或范围 | 可以进入协议 codec，并注明资料版本、页码或章节 |
| 项目配置 | 物理端口、现场站号、节点 ID、方向、通道映射、安全超时 | 必须由版本化配置提供，不得散落在代码中 |
| 现场验证 | 某台实物、某固件版本上的实测行为 | 必须记录设备身份和条件，不得提升为所有设备的默认值 |
| 未解决 | 资料缺失、互相冲突或实物型号未闭环 | 必须保持 `null`/`UNCONFIGURED`，禁止实际 `arm` |

### 2.3 已知资料冲突的强制处理

- X6 Plus 产品说明书写“出厂 ID 1、油门通道 1”，通用 Hobbywing CAN 协议写默认节点 ID `0x7D`。驱动必须通过单机调试/查询确认，不得任选其一。
- Hobbywing 通用协议默认 CAN 位率为 `500 kbit/s`，这里配置为 `1 Mbit/s`。同一物理 CAN 接口上的所有节点必须使用同一实测位率；否则必须拆分接口。
- BD-201S 的 V2.5 PDF 与文件名为 5.9 的 `.doc` 在拨码、地址范围和寄存器映射上实质不兼容，不能按文件日期或版本号自动合并。真实驱动必须显式选择经硬件/固件确认的 `bd201s_v25` 或 `bd201s_v59` profile。
- `exa/继电器/ZS10IO.md` 中的 `/dev/ttyS0`、站号 `0x42` 和 Y1～Y7 功能是 K2-gamma 配置，不是 Snappy 默认值。
- UBS 示例代码的波特率码表与手册冲突，以手册第 4 页为准；示例代码不得直接复用。
- KS114 的 FC `0x03` 字段具有设备专用语义，不能由严格通用 Modbus“读寄存器数量”接口代替。
- IMU 文档的 CRC 表头、`0x61` 含义、带宽码等存在冲突；标准 Modbus 帧例可以确认 CRC 低字节先发，但冲突寄存器在型号和固件确认前必须禁用。
- XM8588 的负校正值公式有算术错误；如未来需要校正，必须按标准有符号 16 位二补码实现并通过实机向量验证。

## 4. 驱动分层和代码边界

### 4.1 强制分层

每种真实设备必须按以下依赖方向实现：

```text
control/service
      ↓
device driver（物理量、状态、设备语义）
      ↓
protocol codec（纯编解码、校验、寄存器/帧常量）
      ↓
bus transport（SocketCAN / RS485 串行事务）
```

已有通用 bus transport 和 Modbus RTU 组件必须复用；只有设备接入暴露出确实缺失的通用能力时才修改 bus 层，禁止为每个 RS485 设备复制串口 owner、队列或 CRC 实现。

- 总线层必须不知道“风扇”“爬绳器”或“超声波”等业务含义。
- codec 必须尽可能是无 I/O 的纯函数，输入字节/结构，输出结构化结果。
- 设备层不得向控制层暴露原始 CAN 帧、寄存器地址或 CRC。
- 控制层不得直接拼帧、写寄存器或按继电器编号执行业务。
- `exa/` 只作为协议证据，不得加入正式构建目标。

推荐目标结构如下；迁移可以分步进行，但新真实驱动不得继续堆入单一 `interfaces.hpp`：

```text
rk3588/drivers/
├── include/snappy/drivers/
│   ├── bus/
│   ├── protocols/
│   └── devices/
├── src/
│   ├── bus/
│   ├── protocols/
│   └── devices/
└── tests/
    ├── protocols/
    ├── devices/
    └── hil/

simulator/fake-hardware/
└── include|src/.../fakes/
```

### 4.2 总线所有权和并发

- 每个 CAN 接口和每个 RS485 串口必须只有一个 owner 线程或事件循环。
- 设备驱动必须通过有界请求队列提交事务，禁止多个线程同时读写同一文件描述符。
- 安全停止必须具有高于普通轮询和普通写命令的优先级。
- 所有事务必须携带基于单调时钟的 deadline；禁止无期限阻塞、detached thread 和无界队列。
- RS485 调度器必须在设备间串行交易，并为多只超声波提供声学错峰调度。
- 引用同一物理 RS485 端口的设备必须配置完全相同的波特率、数据位、校验位和停止位；`station_id` 只要求在该物理端口内唯一。配置加载时必须拒绝同端口串口参数冲突和站号重复。

### 4.3 后端类型

同一业务接口必须支持且明确区分：

- `fake`：确定性、无真实 sleep、可注入故障，供整仓和契约测试使用。
- `unconfigured`：始终 fail-closed，明确返回配置缺失，不进行 I/O。
- `real`：只有配置完整且 Schema 校验通过后才可进入输出受抑制的诊断构造/自检；未通过相应 HIL 和部署门禁时不得进入生产 `arm`。

`real` 缺少任一必需参数时，该设备必须选择或保持 `unconfigured`，其 `start` 和 I/O 均 fail-closed 且不得访问设备节点；control 可以继续运行在诊断/安全模式，但必须拒绝 `arm`，绝不得静默回退为 fake。

公共 API 中 `start()` / `stop()` 只表示驱动生命周期启动和关闭；`safe_stop()` 表示执行设备定义的安全输出计划。普通运动停止必须使用明确的动作名，例如 `stop_motion()`、`command_zero_throttle()` 或 `cancel_motion()`；`disable()`、`deenergize_all()` 仍保留各自设备语义，禁止把这些概念都命名为 `stop()`。

### 4.4 能力成熟度和声明用语

代码评审、日志和发布说明必须使用以下状态，禁止把“对象可构造”写成“设备已支持”：

| 状态 | 含义 | 允许动作 |
|---|---|---|
| `specified` | 本文已定义可追溯协议子集和阻断项 | 只允许设计、fake 和 codec 工作 |
| `implemented` | codec/设备代码及无硬件测试通过 | 仍不得声称真实设备可用 |
| `diagnostic_ready` | 完整配置可构造 real，并以输出受抑制方式完成身份/只读自检 | 仅 maintenance/台架诊断 |
| `hil_qualified` | 指定型号、固件和总线适配器通过设备级 HIL | 可以声明“该 profile 已通过设备级 HIL” |
| `deployment_qualified` | 在目标机器人共享总线、电源和安全回路中通过集成测试 | 才可以为该部署启用生产 `arm` |

“支持某设备”至少必须指明 `model`、`protocol_family`、`protocol_profile` 和 `hil_qualified` 证据；“在 Snappy 目标机器人中支持”必须达到 `deployment_qualified`。第 9 节是这些状态的统一验收清单。

## 5. 公共总线协议要求

### 5.1 Modbus RTU

- 帧必须按 `[站号][功能码][数据][CRC_L][CRC_H]` 编码。
- CRC 必须使用初值 `0xFFFF`、多项式 `0xA001`，线上低字节先发。
- 寄存器地址、数量和 16 位寄存器数据按高字节先发；有符号值必须显式按二补码解码。
- 每次响应必须校验站号、功能码、长度、字节数、CRC、异常响应以及与当前请求的对应关系。
- 串口层必须累计短读，不能假设一次 `read()` 返回完整帧。
- 总线调度必须满足至少 3.5 个字符时间的 RTU 帧间静默，并使用单调 deadline。
- 只有无副作用的读取可以按设备策略自动重试。启动、运动、换向、地址/波特率修改、保存参数等写操作不得盲目重放。
- 写单寄存器/线圈的回显只证明设备接受了协议值；需要真实状态时必须另行读回，且继电器线圈读回不等于机械到位。
- 修改地址、位率、校准或 Flash 参数必须处于 maintenance 模式，逐台隔离设备，写前记录旧值，写后按新参数重连并读回身份。

KS114 虽使用 Modbus RTU 外壳，但其测距 FC `0x03` 的数量字段被用作探测命令。它必须拥有独立 `Ks114Codec`，不得经由会强制数量合法性的通用 `read_holding_registers()` 路径。

### 5.2 Classic CAN

- 每个 codec 必须显式规定 11/29 位 ID、RTR/错误帧处理、DLC、字节序、缩放、范围和应答规则。
- 接收过滤器必须限定目标 ID/帧型；不得把总线上的任意同长度帧当作响应。
- 总线 `BUS_OFF`、接口重启、RX overflow 和持续 TX timeout 必须进入可观测故障状态。
- 改节点 ID 或位率属于 maintenance 操作，必须逐台接入，并在重新上电后验证。
- 同一物理接口上的模块只有在共同位率经配置与实测确认后才可并网。当前配置中的具名 CAN map 仍为空，且没有 Schema、loader 或实测拓扑，不能证明两者可共存；未确认时必须保持 `UNCONFIGURED` 或拆分物理接口。

### 5.3 样本、健康和时间

- 设备生命周期、设备健康、样本质量必须分开表达。
- 进程内传感器样本必须携带逻辑设备、物理单位、采样单调时间和 `GOOD/STALE/INVALID/UNKNOWN`；对外 JSON 快照必须输出 `age_ms`，不得跨进程比较不同启动域的单调时间点。
- CRC 错误、越界原始值、错误站号、错误帧型不得产生 `GOOD` 样本。
- 设备无新数据超过配置的陈旧阈值后，最后值可以保留用于诊断，但质量必须变为 `STALE`，安全逻辑不得把它当新鲜值使用。

## 6. 设备专用规范

### 6.1 Hobbywing X6 Plus 推进/附着风扇

#### 6.1.1 已确认协议

- 目标动力套型号为 X6 Plus，电机标识 `6218-150KV`；产品资料给出 12～14S、最高 61 V，电调持续 25 A、瞬时 80 A，环境温度 -20～50°C。最终供电和保护仍必须由电气设计确认。
- CAN 线色资料为黄 GND、灰 CAN-H、绿 CAN-L；黑/白为 PWM 油门。现场接线仍必须按连接器和实物标签复核。
- HW-UAVCAN 基于 CAN 2.0B，使用 29 位扩展数据帧。
- Message 帧为广播，Service 帧为请求/响应；CAN payload 最大 8 字节，最后一字节为 tail byte。
- 单帧 tail 必须 `start=1`、`end=1`、`toggle=0`；Transfer ID 范围 `0..31`，同一类型每包递增并循环。
- 29 位 arbitration ID 不能直接等于下表的 Data Type ID。当前资料/示例确认的构造为：

```text
message_id = (priority[4:0] << 24) | (data_type_id[15:0] << 8) | source_node_id[6:0]
service_request_id = (priority[4:0] << 24)
                   | (service_type_id[7:0] << 16)
                   | (1 << 15)
                   | (destination_node_id[6:0] << 8)
                   | (1 << 7)
                   | source_node_id[6:0]
service_response_id = (priority[4:0] << 24)
                    | (service_type_id[7:0] << 16)
                    | (1 << 15)
                    | (destination_node_id[6:0] << 8)
                    | source_node_id[6:0]
```

  bit15 表示 service，bit7 表示 request；response 公式保留 bit15 并清除 bit7。响应中的 source 必须是被请求 ESC，destination 必须是本机请求节点。codec 必须分别表示 priority、message/service、request/response、source/destination node，并按 service type、节点对和 transfer ID 关联请求与响应；过滤器不得把 `0x4E52` 等 Data Type ID 直接当完整 CAN ID。
- 通用协议支持 `1M/500k/250k/200k/100k/50k`，默认 `500 kbit/s`。
- 节点可配置范围 `1..0x7D`；`0`、`0x7E`、`0x7F` 保留。
- `RawCommand` 类型为 20100（`0x4E84`），优先级 HIGHEST。
- 四通道命令把四个有符号 14 位油门值打包为 7 字节，随后附 tail byte。
- 油门协议范围为 `-8191..8191`；X6 当前不支持负 CAN 油门，驱动必须在编码前拒绝负值。`0` 为停机，`8191` 为满油门。
- 厂商给出的 CAN 油门发送周期为 2.5 ms（400 Hz）。正式发送周期必须可配置，并通过 RK3588 调度和总线负载测试验证，不能仅凭普通 Linux 定时器假定 400 Hz 可达。

除 RawCommand 外，已确认的维护/控制类型包括：

| Data/Service Type ID | 语义 | 使用约束 |
|---:|---|---|
| 20012 / `0x4E2C` | 全总线油门使能 `0xAA`、失能 `0x55` | 正常控制与安全停止必须有明确状态机 |
| 20013 / `0x4E2D` | 广播查询 ESC ID/油门通道 | commissioning/诊断使用 |
| 20014 / `0x4E2E` | 设置 ID 模式/启动命令要求 | maintenance 使用 |
| Service 210 / `0xD2` | 单设备设置 ID 和通道 | 总线上只能连接一台 ESC |
| Service 220 / `0xDC` | 已知旧 ID 时设置 ID 和通道 | 多设备场景仍需机械隔离与回读 |
| Service 211 / `0xD3` | 设置 CAN 位率 | 重新上电并按新位率验证 |
| Service 214 / `0xD6` | 设置/读取遥测频率 | 频率资料存在冲突，必须实测 |
| Service 215 / `0xD7` | 选择 PWM/CAN 油门 | 启动时验证当前来源 |
| Service 216 / `0xD8` | 读取自检结果 | arm 前必须检查 |

状态上报：

| 帧类型 | Data Type ID | 内容 | 缩放/说明 |
|---|---:|---|---|
| MSG1 | 20050 / `0x4E52` | RPM、PWM/油门、16 位状态 | PWM `0..8191`；某章节称默认 10 Hz，但资料有冲突，需实测 |
| MSG2 | 20051 / `0x4E53` | 母线电压、电流、温度 | 电压 `/10 V`，电流 `/10 A` |
| MSG3 | 20052 / `0x4E54` | MOS、电容、电机温度 | 不支持的温度通道可能返回 0 |

MSG1 状态必须至少解码：过压、欠压、过流、堵转、油门丢失、MOS/电容过温、电机断线、MOS 开/短路、通信异常和方向标志。协议不同章节对默认/最高遥测频率存在矛盾；10 Hz 和最快 50 ms 只能作为需要实机核对的资料值，不得据此承诺生产刷新率。

v1 批准的运行时控制和状态子集仅接受单帧 transfer，即 tail 的 `start=1`、`end=1`、`toggle=0`。收到多帧起始/中间/结束 tail 时必须返回稳定的 unsupported 错误，且不得更新状态。任何需要多帧的 maintenance 请求或响应在实现 signature CRC、transfer-ID 隔离、toggle 校验、有界重组和对应错误测试前保持禁用。

本小节的 ID 构造与 tail 来源于通用协议第 6～9 页及 `exa/推进风扇/example/hobbywing_can.cpp:35-80`；控制/状态/维护类型来源于协议第 11～30 页。

#### 6.1.2 配置和启动

- 左右风扇必须配置不同的节点 ID 和不同的 throttle channel。
- 节点 ID/油门通道配置必须一次只连接一台电调，拆桨或采取等效机械隔离。
- 产品说明书的默认 ID 1 与通用协议默认 `0x7D` 冲突；启动不得仅靠默认值。commissioning 工具必须查询并记录 SN、节点 ID、通道、位率和固件版本。
- 节点处于 `0x7D` 时通用协议称其不主动上报，驱动不得把“无状态帧”直接解释为设备断电，必须结合配置状态判断。

#### 6.1.3 安全要求

- HW-UAVCAN codec 可以提供具名 raw packing；设备接口必须向 control 暴露归一化 `set_throttle_pct()`、明确的 `command_zero_throttle()`、状态读取和故障复位，禁止 control 直接传 packed 14-bit 数据。
- 20012 是全总线使能/失能，不得实现成某一风扇实例的生命周期 `stop()` 或运动停止。单风扇 `command_zero_throttle()` 必须只把该 throttle channel 置零而不破坏另一通道；全总线失能只能由风扇组/安全监督器在所有通道已进入确定安全目标后执行。
- 任何负值、超过 `8191`、非有限换算或未知 throttle channel 必须在发送前拒绝。
- 油门丢失约 0.25 s 后设备会关闭输出；该行为是最后防护，不得代替本机 lease/watchdog。厂商说明信号恢复后可能恢复功率，因此 Snappy 在链路恢复后仍必须保持新 epoch、重新 acquire/arm 的系统规则。
- 堵转保护可能锁存到重新上电。驱动必须上报故障并阻止自动重启；不得自动循环断电清故障。
- 产品资料还称瞬时电流接近 300 A 时设备会重启，连续 6 次异常后关闭输出。Snappy 必须把异常重启/状态中断视为 fault，不得继续发送非零目标等待其自行恢复。
- X6 手册说明温度超过 110°C 主要是告警而非可靠降额保护。温度阈值和处置必须由本机安全配置与实机验证确定。
- `SAFE_HOLD` 下保持附着转速还是归零由上层安全监督器决定；低层驱动不得自行推断。风扇组 `safe_stop()` 必须执行安全监督器批准的 fan-group safe plan，它不等同于单通道 `command_zero_throttle()`；驱动仍必须能够明确执行零油门并持续报告发送和反馈状态。

#### 6.1.4 最低测试

- 单帧 tail、Transfer ID 循环、四通道 14 位 packing golden vectors。
- `-1`、`8192`、错误通道和错误扩展帧拒绝测试。
- MSG1/2/3 正常、短帧、错误 ID、错误 tail 和故障位解码测试。
- 两台不同 ID/通道的 fake 联动、丢状态、TX timeout、BUS_OFF 和堵转锁存故障注入。
- HIL 必须验证共同位率、实际方向、零油门、失信号和断连后的不自动续跑。

#### 6.5.2 驱动状态机

位置状态与设备健康必须分开维护。无反馈基线至少使用 `UNKNOWN/MOVING_EXTEND/MOVING_RETRACT/ASSUMED_REACHED`；故障属于健康维度，不用一个含混的 `FAULT` 同时代替位置和健康。

必须分开配置两个单调计时器：

- `expected_travel_time_ms`：仅用于经过标定的“走到预计端点”动作；正常到期后先失电并读回继电器 OFF，才可以报告 `ASSUMED_REACHED`。
- `max_energized_time_ms`：独立硬截止，必须大于预计行程时间并覆盖容差；一旦触发，立即失电，位置变为 `UNKNOWN`，健康进入 `FAULT`，禁止报告到位。

普通短点动或远端主动缩短的动作在停止后保持 `UNKNOWN`，不得因为任意软件计时结束就报告 `ASSUMED_REACHED`。远端参数只能缩短动作，不能延长本地硬截止。

| 事件 | 位置状态 | 健康/控制结果 |
|---|---|---|
| 启动且无位置反馈 | `UNKNOWN` | 继电器自检结果决定 `GOOD/FAULT` |
| 预计端点计时正常完成且输出确认 OFF | `ASSUMED_REACHED` | 保持 `GOOD`；明确标记为推定值 |
| 操作者提前 `cancel_motion()` | `UNKNOWN` | 若失电成功，设备健康可保持 `GOOD` |
| lease 丢失或进入安全保持 | `UNKNOWN` | control 进入 `SAFE_HOLD`；失电失败则设备 `FAULT` |
| `max_energized_time_ms` 到期 | `UNKNOWN` | 设备 `FAULT`，需明确复位/检查 |
| 可观测过流、互锁冲突或反馈矛盾 | `UNKNOWN` | 设备 `FAULT` |
| 急停 | `UNKNOWN` | control 进入 `ESTOP_LATCHED`；不得自动续跑 |

- 最大通电截止必须使用单调时钟，即使线程、网络或系统时间异常也必须执行。
- 每次换向必须先全部断电并等待配置的死区。
- 过流保护器若没有可读反馈，只能作为独立断电保护，软件不得虚构“已检测到过流”；应通过可读触点/电流传感器或后续人工检查确认故障原因。
- 启动时不得根据上次命令恢复运动；无反馈时初始位置始终为 `UNKNOWN`。

#### 6.5.3 配置门禁

每个推杆至少需要：逻辑 ID、完整选型代码、两路继电器映射、实测 extend/retract 方向、额定电压、行程、`expected_travel_time_ms`、`max_energized_time_ms`、`reversal_deadtime_ms`、过流阈值/保护器、停机电气模式以及可选反馈通道。配置必须验证 `0 < expected_travel_time_ms < max_energized_time_ms`。刮条和毛刷机构必须分别标定，不能因为电机同系列而共享未经验证的方向/时间。任一关键项缺失时必须保持未配置。

#### 6.5.4 最低测试

- fake 时钟下的伸出、缩回、超时、`cancel_motion()`、重复取消、生命周期 `stop()` 和反向切换。
- 证明两路继电器从不同时 ON，并证明普通命令无法延长本地最大通电时间。
- 覆盖预计端点、提前取消、硬截止、lease 丢失和急停的状态表；无反馈时不得出现真实 `REACHED`。
- HIL 必须验证方向、全行程时间、堵转电流、过流保护、失电保持和实际机械限位。

### 6.6 UBS1000-C18R-485 左右超声波

#### 6.6.1 已确认协议

- 目标系列型号为 `UBS1000-C18R-485`（项目资料中的连字符写法需以铭牌确认），量程 60～1000 mm。
- 默认地址 1、`9600 8N1`，RS485 Modbus RTU。
- FC `0x04` 输入寄存器：

| 地址 | 值 | 解码 |
|---:|---|---|
| `0x0000` | 距离 | uint16，`raw / 10 = mm` |
| `0x0001` | 内部温度 | int16，单位 °C |
| `0x0002` | 飞行时间 | uint16，单位 μs |

- FC `0x03/0x06/0x10` 保持寄存器：`0x0000` 外部温度、`0x0001` 温补来源（0=内部，1=外部）、`0x0002` 位率码、`0x0003` 工作模式（0=单次可控，1=持续测量）、`0x001F` 站号。
- 位率码为：01=2400、02=4800、03=9600、04=14400、05=19200、06=38400、07=56000、08=57600、09=115200、0A=128000、0B=256000。
- `0xFF` 特殊地址只允许在总线上仅有一台设备时查询真实地址。
- 异步测量频率为 16 Hz；同步/单次模式由主机访问触发。

#### 6.6.2 物理和调度要求

- 接线资料：棕电源正、蓝电源负、白 RS485-、黑 RS485+；实际 M12 针脚仍需供应商图纸确认。
- 两只设备出厂地址相同，必须逐台隔离修改为不同站号后才能并网。
- 地址维护必须使用旧站号通过 FC `0x06` 写 `0x001F`；位率维护通过 FC `0x06` 写 `0x0002`。写回显有效后，maintenance 工具必须切到新站号/位率读取 `0x0000..0x0002`，再断电重启复查掉电保持。资料没有把“立即生效的精确字节时点”定义成主机可依赖行为，因此实现必须容忍写回显后旧参数失联，并禁止自动重写。
- 并排探头间距应大于探测距离的一半；应避免强风、明显温度梯度和与动力线同管。
- 多超声波必须由统一调度器错峰触发，不能让 UBS 与 KS114 同时发射造成串扰。
- 外部温补必须先写外部温度，再把选择位写 1。
- 手册没有响应超时；正式值必须通过实测确定。示例中的 100/1000 ms 不能直接成为生产默认。

#### 6.6.3 禁用项和测试

- 示例代码的波特率码表、单次 `read()` 和 FC `0x10` 未校验 CRC 路径不得复用。
- 最低测试包括所有寄存器缩放、负温度、部分帧、CRC/站号错误、16 Hz/陈旧转换、双设备独立站号和声学错峰。
- HIL 必须确认精确型号、供电上限、针脚、安装角、盲区、互扰和最坏响应时间。

本小节寄存器、模式值和位率码来源于 UBS 手册第 1～4 页；示例代码只用于反例和辅助帧核对。

### 6.7 KS114 前后/向下超声波

#### 6.7.1 已确认协议

- 目标变体为 `KS114-MODBUS` RS485；接口是出厂固化变体，不能把 TTL/I2C 版本当作可切换设备。
- 默认 `9600 8N1`，默认站号 `0x10`。
- 仅允许 40 个站号：`0x10..0x1F` 与偶数 `0xD0..0xFE`。
- 上电自检约 1200 ms，并主动输出初始化信息；驱动必须等待启动完成并丢弃/单独解析该非请求响应数据。
- 设备专用测距请求外形为 `[ID][0x03][0x00][0x02][0x00][command][CRC_L][CRC_H]`，响应返回一个 16 位结果；最后两个数据字节是探测命令，不是标准寄存器数量。

v1 基线 profile 只批准 `0x01`（直接返回 mm），但必须先在目标实物上确认量程。其他命令是可选候选，只有单独配置 `measurement_profile`、单位、量程和 HIL vector 后才能启用：

| 命令 | 返回单位 | 资料范围/执行时间 |
|---:|---|---|
| `0x05` | μs，`/58 = cm` | 1～50 cm，≤9 ms；默认禁用 |
| `0x0A` / `0x02` | μs，`/58 = cm` | 1～70 cm，≤9 ms；默认禁用 |
| `0x0F` | μs，`/58 = cm` | 1～110 cm，≤9 ms；默认禁用 |
| `0x01` | mm | v1 基线；资料称最长 5 m，≤33 ms，实际量程需实物确认 |
| `0xB0` | mm | 与 `0x01` 的差异资料不足，默认禁用 |
| `0xB2` | μs | 1 cm～5 m；默认禁用 |
| `0xB3` | μs | 配合 `0xB1` 对射；默认禁用 |
| `0xBA` | μs | 25 cm～3 m，依赖盲区配置；默认禁用 |

`0xBC` 的单位在手册中冲突，v1 必须禁用，直到实机 golden vector 明确。

#### 6.7.2 配置和调度

- 改站号：使用 FC `0x06` 向寄存器 `0x0004` 依次写 `0x009A`、`0x0092`、`0x009E`、新站号；每一步必须收到与请求完全一致的回显后才进入下一步。
- 改位率/其他配置：使用 FC `0x06` 向 `0x0004` 依次写 `0x009C`、`0x0095`、`0x0098`、新值；位率码 `0x77/0x78/0x79` 对应 9600/57600/115200。
- 手册没有给出可依赖的步骤间 delay、生效瞬间和掉电确认应答。maintenance 工具不得猜固定 sleep；应以逐步回显和总 deadline 驱动，写完后切换新参数读取状态，并通过断电重启验证持久化。
- 多台出厂地址相同，必须逐台隔离 commissioning。
- 多只传感器必须串行触发；调度间隔至少覆盖命令最大执行时间 9/33 ms 加总线周转和实测余量。
- 接线资料为黄 A、白 B；电源版本存在 3～5.5 V 与高压定制范围冲突。接 24 V 前必须用铭牌/订单证明实物是高压定制版。

#### 6.7.3 最低测试

- 专用 FC `0x03` codec、全部启用命令的单位和 CRC golden vectors。
- 非法站号、上电主动报文、配置序列错序/错回显、超时、错误单位和短帧测试。
- 多传感器错峰、前后/向下逻辑 ID 独立性和陈旧样本测试。
- HIL 必须验证供电版本、实际量程/盲区、波束角、站号、互扰和安装方向。

本小节站号、启动和配置序列来源于 KS114 手册第 5～11 页。`exa/超声波传感器（前后）和毛刷位置检测（向下）/example/ks114_controller.cpp` 的启动报文字段偏移与手册不一致，不得作为权威解析实现。

### 6.8 RS02A / Wit 兼容 IMU

#### 6.8.1 身份门禁

项目清单使用“RS02A”，资料中出现 `WTGAHRS02A`，SDK 又是多型号通用包。三者身份尚未闭环。协议的 `0x2E` 只能读取版本，不能证明具体型号；身份必须由实物铭牌/订单证据加版本读回共同建立。真实驱动类可以按已确认 Modbus 子集实现 codec，但在身份和轴向验证完成前必须保持 `UNCONFIGURED`，不得作为姿态安全输入。

#### 6.8.2 已确认核心子集

- 默认地址 `0x50`、`9600 8N1`；FC `0x03` 读、FC `0x06` 写并回显。
- 地址寄存器 `0x1A`，合法 `0x01..0x7F`。
- 位率寄存器 `0x04`：1～7 对应 4800、9600、19200、38400、57600、115200、230400；更高速率只属于资料列出的特定型号。
- 核心读取：

| 地址 | 数据 | 解码 |
|---:|---|---|
| `0x34..0x36` | AX/AY/AZ | int16，`raw / 32768 × 16 g` |
| `0x37..0x39` | GX/GY/GZ | int16，`raw / 32768 × 2000 °/s` |
| `0x3D..0x3F` | Roll/Pitch/Yaw | int16，`raw / 32768 × 180°` |
| `0x40` | 温度 | int16，`raw / 100 °C` |

- 写配置必须在 10 s 解锁窗口内完成：向 `0x69` 写 `0xB588` → 修改 → 向 `0x00` 写 `0x0000` 保存。常见流程要求解锁后等待 100 ms；加速度校准后等待 2 s。
- 改位率后必须先切换主机位率，再重新解锁和保存。

#### 6.8.3 禁用和安全要求

- 普通启动必须是只读流程，所有 FC `0x06` 默认拒绝；不得自动校准、改站号、改位率或保存 Flash。
- baseline maintenance 白名单仅包括在身份已闭环、单设备隔离和操作者明确确认后修改 `0x1A` 地址、`0x04` 位率及按协议保存。`0x01` 校准/角度参考等写操作因资料冲突保持禁用，直到型号专用 profile 和 HIL 程序批准。
- `0x61` 的“静止阈值/自动校准开关”、CALSW 描述、带宽码和 BASELINE 公式存在冲突；v1 不得开放这些写操作。
- SDK 中的 fd 优先级、位率扫描、响应站号校验和 RS485 方向控制实现不得直接复制。
- 安装坐标轴、正方向和机器人坐标变换必须通过静态六面/姿态试验确定；未确认时姿态质量为 `UNKNOWN`。

#### 6.8.4 最低测试

- 核心寄存器的正负极值和缩放、CRC 低字节先、错误站号/功能码/长度/异常响应。
- 解锁窗口、写回显、保存序列和配置命令在普通运行模式下被拒绝。
- fake 姿态越限、陈旧、跳变和无效样本故障注入。
- HIL 必须确认型号/固件、供电、针脚、位率、地址、轴向、静置零偏和动态方向。

本小节寄存器和缩放来源于 `exa/陀螺仪/modbus协议.md` 的寄存器表、读寄存器示例和写配置流程；通用 SDK 只能辅助核对，不能扩展已确认寄存器集合。

### 6.9 XM8588B 风速传感器

#### 6.9.1 已确认协议

- `XM8588B` 为 RS485 型号；M/V10 模拟量型号不得共用该驱动。
- 量程 0～30 m/s，精度 ±3%，供电 12～24 V。
- 默认站号 1、`9600 8N1`；有效站号 1～249。
- FC `0x03` 读取，FC `0x06` 修改配置；风速寄存器 `0x0000`，`raw / 100 = m/s`。
- `0x0066` 为设备地址，`0x0067` 为位率码：1=2400、2=4800、3=9600、4=19200、5=38400、6=115200。
- `0xFA` 通用地址只允许在总线上只有一台设备时查询真实站号。
- 地址和位率修改立即生效；位率修改可能没有旧位率下的响应，maintenance 工具必须切换新参数后读回身份。

#### 6.9.2 v1 边界和测试

- v1 只实现查询模式。主动上传模式的帧、周期和恢复规则资料不足，必须禁用。
- `0x0064/0x0065` 按较新正文保守视为只读；校正寄存器在公式冲突解决前不开放。
- real 配置至少必须包含物理端口、站号、位率、`poll_interval_ms`、`response_deadline_ms` 和 `stale_after_ms`；任一缺失时不得作为风速安全输入。
- `raw=0` 是合法零风读数，单靠该值不能区分零风与叶轮卡滞；如安全需求要求卡滞诊断，必须增加独立诊断证据，不能由驱动猜测。
- `raw>3000` 超出已确认 0～30 m/s 量程，样本必须标为 `INVALID` 并记录错误；连续越界达到配置阈值后设备健康进入 `DEGRADED/FAULT`，不得把数值截断为 30 m/s。
- 接线资料为红 VIN、绿 GND、黄 A+、蓝 B-；仍应以实物标签为准并断电接线。
- 最低测试包括 `/100` 缩放、0/30 m/s 边界、错误站号/CRC、立即切换参数流程、陈旧样本和查询模式限定。
- HIL 必须确定刷新周期、最坏响应时间和安装方向，并评估是否存在足够的独立证据区分叶轮卡滞与真实零风；若没有，该不可辨识限制必须进入安全分析和部署资格记录，禁止声称驱动仅凭零读数即可诊断卡滞。

本小节型号、寄存器和配置来源于 XM8588 手册第 2、5、8～11 页；负校正值公式存在错误，因此 v1 不开放校正写入。

## 7. 配置和 commissioning 规范

### 7.1 配置必须表达的内容

每个真实设备至少必须配置：

- 唯一逻辑 ID、`model`、`protocol_family`、`protocol_profile` 和 `enabled` 状态。
- 每个设备自己的 backend 类型/选择；禁止用一个全局 `backend` 掩盖部分设备已确认、部分设备仍未配置的现实，也不得把 backend 类型与生命周期、健康或成熟度状态混为一谈。
- 物理总线 ID；CAN 接口/位率或 RS485 端口/位率/8N1。
- 现场节点/站号以及其来源（铭牌、读取、commissioning 记录）。
- 方向、通道、缩放和安装角色。
- 带单位后缀的请求 deadline、轮询周期和陈旧阈值键，例如 `response_deadline_ms`、`poll_interval_ms`、`stale_after_ms`；这些值必须注明是实测项目参数，不是厂商线协议事实。
- 执行器的限值、`reversal_deadtime_ms`、`expected_travel_time_ms`、`max_energized_time_ms` 和安全停止策略；不同设备可使用更精确的具名键，但不得省略单位后缀。
- 设备资料版本、实物序列号/固件版本和 `hil_record_ref`；该字段必须引用可审计的仓库记录、测试制品路径或外部记录 ID，并避免包含凭据。

未知值必须为 `null` 或缺失后被 Schema 拒绝；禁止使用 `0`、空字符串或“常见默认值”掩盖未知。

配置 Schema 还必须执行跨设备约束：引用同一 CAN 接口的所有节点必须配置相同 CAN 位率（当前 v1 字段为 `bitrate`；若迁移为 `bitrate_bps` 必须版本化）；若 X6 与 Ti5 不能用共同实测位率，配置模型必须支持两个具名 CAN 接口。引用同一 RS485 端口的设备必须使用同一串口参数且站号唯一。

### 7.2 共享总线 commissioning

commissioning 必须是与生产控制循环分离的显式 maintenance session：操作者确认、执行器输出受抑制、一次只物理连接目标设备，并使用受限 real adapter。生产设备实例缺少已确认站号/节点 ID 时仍必须保持 `UNCONFIGURED` 且不进行 I/O；`0xFF`、`0xFA` 等通用地址和逐台探测只允许在该隔离 session 中使用，禁止生产启动自动扫描共享总线。

1. 断开执行器能量或完成机械隔离，CAN 风扇必须拆桨/等效隔离。
2. 每次只接入一台可能使用默认地址的设备。
3. 读取并记录型号、固件、当前地址/ID、位率和可识别参数。
4. 在 maintenance 模式显式修改，验证每一步回显或按协议处理无应答切换。
5. 重新上电，使用新参数读取身份和基础状态。
6. 完成唯一地址表后再并联设备，检查终端电阻、总线负载和最坏时延。
7. 将结果写入版本化配置和 HIL 记录，并用 `hil_record_ref` 建立引用；生产启动不得重复自动配置。

RS485 默认冲突必须显式解决：继电器、UBS、XM8588 默认均可能为 1，多台 UBS 均为 1，多台 KS114 均为 `0x10`。通用地址 `0xFF`/`0xFA` 只允许单设备隔离状态使用。

## 8. fake、故障注入和契约一致性

- fake 与 real 必须实现同一设备接口，使用相同单位、范围、状态和错误码。
- fake 必须可注入：超时、短帧、CRC 错误、错误站号/ID、写回不一致、陈旧样本、设备 fault、BUS_OFF、继电器粘连模拟和传感器跳变。
- fake 时间必须由可注入单调时钟推进，不得依赖真实 sleep。
- fake 不得因为测试方便而接受 real 会拒绝的越界值或非法状态转换。
- `Unconfigured...` 必须始终 fail-closed，且错误能指出缺失的具体配置项。

## 9. 真实驱动 Definition of Done

下列 1～7 和 11 是所有设备 profile 达到 `hil_qualified` 的通用条件；第 8 项只适用于执行器，第 9 项只适用于传感器。第 10 项是达到 `deployment_qualified`、并声称“在目标 Snappy 机器人中支持”的附加条件：

1. 型号、供电、接口和固件身份有实物证据。
2. 该 `protocol_profile` 已批准子集内的所有协议常量均可追溯到资料版本/页码或批准的实测记录；规范禁用项必须被显式拒绝。
3. 配置 Schema 完整，缺失/未知/越界值 fail-closed。
4. codec golden vectors 覆盖正常、边界、错误和异常响应。
5. fake/real 使用相同接口，fake 契约和故障注入全部通过。
6. timeout、重试、读回、陈旧和健康状态转换有单元测试。
7. 生命周期 `stop()`，以及该 profile 适用的 `safe_stop()`、`stop_motion()`、`command_zero_throttle()`、`cancel_motion()`、`disable()`、`deenergize_all()` 等设备动作必须分别命名、幂等，并验证优先级和最终可观测状态。
8. 执行器完成方向、限值、断连、掉电、急停和恢复不自动续跑的 HIL。
9. 传感器完成单位、安装方向、量程、刷新率、陈旧阈值，以及适用时的互扰 HIL。
10. 在目标机器人上完成共享 CAN/RS485 总线负载、地址冲突、噪声、终端和故障恢复测试，并覆盖目标电源、硬件急停、继电器失电、外置看门狗、进程退出、IPC/lease 超时及恢复不自动续跑的集成证据。
11. `./tools/test-all.sh` 和 `./tools/run-fake.sh` 通过，验证证据保存在提交、代码评审或 CI 记录中。
